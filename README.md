# 高校成果库 · 作者身份归并

跨系统作者记录归并工具：导入 CSV、按来源整源刷新名册、逐对判定“同一人 / 不同人”、撤回判定、查看当前分组，并导出 `record_id → group_id` 映射供论文关联使用。Flask + SQLite，单容器可运行。

## 快速启动（Docker Compose）

```bash
docker compose up --build        # http://localhost:8000
```

数据保存在命名卷 `identity-data` 的 `/data/identity.db`，`docker compose down` 后数据仍在（`down -v` 才会清除）。

## 本地直接运行（无 Docker）

```bash
python3 -m pip install -r requirements.txt
DB_PATH=./data/identity.db python3 app.py     # http://localhost:5000
# 或生产模式：
DB_PATH=./data/identity.db gunicorn -b 0.0.0.0:8000 --workers 1 --threads 8 app:app
```

## 演示流程（约 2 分钟）

1. 打开首页，点击「下载示例 CSV」，再把它上传导入（10 条记录，来自 CNKI / 万方 / Scopus / Crossref）。
2. 浏览「记录」表（可按 ID / 姓名 / 单位筛选），确认示例中的跨库同名记录：
   - `CNKI-1001`、`WANFANG-2001`、`SCOPUS-3001`（清华·张伟）→ 判为同一人。
   - `CROSSREF-4001`、`CNKI-1002`（北大·李娜）→ 判为同一人；`WANFANG-2002`（北大·李娜，生命科学学院）→ 判为不同人。
   - `CROSSREF-4002`、`SCOPUS-3002`（复旦·王芳）→ 判为同一人。
3. 勾选两条记录（自动填入下拉框）→ 点「判定为同一人 / 不同人」。
4. 「当前分组」实时显示合并结果；点任意判定行的「撤回」，分组立即按其余判定重算。
5. 点「下载映射 CSV」得到 `record_id,group_id` 文件。
6. 打开「整源刷新」，选择来源（如 `CNKI`），上传该来源的**完整**四列 CSV → 预览新增/更新/恢复/停用 → 确认。

### 值得演示的规则

| 规则 | 操作 | 预期 |
| --- | --- | --- |
| 传递 | A–B 同一人，B–C 同一人 | A、B、C 同组 |
| 冗余直判仍保存 | A、C 已在同组后再判 A–C 同一人 | 判定列表新增一条，分组不变 |
| 撤回不丢后续判定 | 建 A–B、B–C、A–C 三条同一人后撤回 B–C | A、B、C 仍同组（A–C 直判生效）；再撤回 A–C，则分为 {A,B} 与 {C} |
| 冲突指出记录对 | 先判 X–Y 不同人，再构造让 X、Y 间接同组，然后判跨组同一人 | 红色提示列出冲突记录对，判定不保存，分组不变 |
| 并发 | 两个请求同时尝试合并被“不同人”约束隔开的两组 | 最多一个成功；库中不出现“不同人同组” |
| 整源停用 | 上传不包含某记录的完整名册 | 该记录标记停用，原记录与判定保留；不再参与分组与映射下载 |
| 停用不传递 | A–B、B–C 同组后停用 B | A 与 C 分开；停用记录不能作为传递桥梁 |
| 恢复还原判定 | 后续名册重新包含该记录 | 其未撤回判定自动重新参与分组 |
| 恢复冲突整批拒绝 | 恢复后会使已判“不同人”的记录对同组 | 指出冲突记录对，整批不生效，保留刷新前状态 |
| 停用判定可撤回 | 在首页「停用记录的判定」中撤回 | 记录仍停用，判定不再生效 |
| 重复/跨源 ID | 名册内有重复 ID，或 ID 属于其他来源 | 整批拒绝，数据库不变 |
| 清空来源 | 上传仅含表头的 CSV | 该来源全部记录停用，其他来源不变 |
| 预览失效 | 预览后新增/撤回判定或导入记录，再确认 | 拒绝旧确认，要求重新预览 |
| 普通导入保护 | 普通导入包含已停用 ID 或改换 ID 的来源 | 整批拒绝 |

## 数据格式

导入 CSV 必需四列（表头可用中文或英文，大小写不敏感，支持带 BOM 的 UTF-8 与 GB18030）：

```
record_id,source,name,org
CNKI-1001,CNKI,张伟,清华大学计算机科学与技术系
```

也接受 `唯一记录ID,来源,姓名,单位`。按 `record_id` 幂等导入：再次导入同 ID 会更新姓名/单位；文件内重复 ID 以最后一行为准。任一数据行缺值则整批拒绝，不写入半成品。**普通导入不会恢复停用记录，也不允许把某个 ID 改到另一个来源**——这两类情况整批拒绝，请改用整源刷新。

### 整源刷新

- 选择来源并上传该来源的**完整**名册（同样四列）。名册中的记录若已存在则更新并保持/恢复启用；名册中不存在的该来源记录被**停用**（保留数据与判定）。
- 仅含表头的 CSV = 清空该来源（全部停用）。
- 整批拒绝条件：文件内重复 ID、ID 已被其他来源占用、任意行的 `source` 与所选来源不一致、缺列/缺值。
- 预览会列出新增、更新、恢复、停用与未变化数量；确认前若任何记录或判定发生变化，预览失效需重新预览。
- 若恢复记录会让已判“不同人”的记录对进入同一组，整批刷新被拒绝，刷新前记录、启停状态与判定完全保留，并指出冲突记录对。
- 其他来源的记录完全不受影响；已有记录默认启用。

导出 CSV 为 `record_id,group_id`，只包含启用记录；`group_id` 取组内字典序最小的记录 ID。

## 实现要点

- **判定是可撤销的追加日志**：`verdicts` 表保存每条判定（`same`/`different`），撤回只写 `revoked_at`，不删除；分组不落库，每次从“生效判定”重新做并查集。
- **停用而非删除**：`records.enabled` 标记停用；停用记录保留原记录与全部判定，但不参与分组、不进入映射下载、不能新增判定。分组只使用**两端均已启用且未撤回**的判定，因此停用记录无法充当传递桥梁。
- **恢复即还原判定**：记录重新出现时置回启用，其未撤回判定自然重新参与分组，无需重建数据。
- **恢复冲突原子拒绝**：确认阶段在写事务内先检查事后状态是否存在“不同人”同组，若有则整事务回滚（记录、启用标记、判定全部保持刷新前状态）并返回冲突记录对。
- **同对唯一有效判定**：`UNIQUE INDEX ... WHERE revoked_at IS NULL` 保证同一记录对同时只有一条生效判定；改判会撤回旧行再插入新行（历史仍可审计）。
- **约束检查与写入同事务**：`decide()`、`confirm_refresh()` 都在 `BEGIN IMMEDIATE` 内计算并联查约束，冲突则回滚；进程内另有可重入锁。
- **预览快照指纹**：预览时记录所有记录与判定的 SHA-256 指纹，确认时在同一写事务内重算比对，任何变化都会使旧确认失效。
- **一致性读取**：页面快照（`snapshot()`）与导出（`export_rows()`）都在单个读事务中读取记录、启用标记与判定，不会混合并发变更前后的状态。
- **持久化**：SQLite WAL 模式；停用标记与判定在 Flask 重启、容器重建（保留卷）后仍在。

## 已知限制

- 单批导入（一次一个 CSV），未做分页，记录数很大时页面会变慢。
- 冲突提示仅说明冲突记录对和“未保存”；不提供自动修复，需要人工撤回相关判定。
- 预览与确认需要两次请求；预览数据保存在数据库中，超过一天的预览会被清理。
- 没有登录/权限控制，部署到公网前需自行加认证与 HTTPS。
- 判定时间戳为 SQLite `datetime('now')`（UTC），界面标注为 UTC。
